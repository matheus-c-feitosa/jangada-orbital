# Jangada Orbital: harmonized fire calendar

NASA Space Apps Challenge 2026 · Challenge: **Harmonization of MODIS and VIIRS Hot Spots** · Local Event: Fortaleza, Brazil

**Live app: https://matheus-c-feitosa.github.io/jangada-orbital/**

The app is a static site: it needs no login and no server.

> Built during the hackathon, November 14–15, 2026.

## What it does

Satellites have counted active fire hotspots since 2000, but the record is split between two sensor families that
cannot be compared directly: MODIS (Terra and Aqua, 1 km, since 2000) and VIIRS (375 m; Suomi NPP from 2012,
NOAA-20 from 2018, NOAA-21 from 2023).

Jangada Orbital harmonizes both families into one monthly series in Aqua-MODIS-equivalent detections, for Brazil
from November 2000 to today:
- Terra is converted until July 2002.
- Aqua is observed from 2002 to 2023.
- From 2024, VIIRS is calibrated per state and month of the year.
- Estimated months carry their likely range.

The web app turns that series into a burning activity calendar.

**Areas.** Choose any of these:
- Brazil, one of the 27 states or the 6 IBGE biomes;
- any of 5,570 municipalities, found by name;
- a rectangle or polygon drawn on the map;
- a point and a radius.

**Calendar.** It shows:
- each month × year, with months above the 90th percentile of past years flagged;
- the current month compared pro rata with the usual pace;
- the busiest year, the highest month and the months that usually burn most;
- optional El Niño / La Niña years.

**Other views.**
- Yearly totals, with conversion ranges.
- This year so far against the normal band.
- When the fire season starts and peaks, and how intense it is (fire radiative power, share of night detections).
- A ranking of states, biomes and municipalities, with a side-by-side comparison.

**Map.**
- How many years each 0.1° cell burned.
- This year against normal, by state or biome.
- Near-real-time detections of the last 7 days.

**Downloads and sharing.** The monthly series as CSV, the calendar as a PNG image or a printed A4 report, and a link
that reopens the same area, values and years, ready to send on WhatsApp.

**Method page.**
- Which satellite counts each year.
- How closely the VIIRS satellites agree.
- A held-out validation, with the error measured by the size of the month.

**Interface.** English or Portuguese, dark or light theme, on desktop, tablet and phone.

## Setup

Requirements: Python 3.12+, [uv](https://docs.astral.sh/uv/), a free
[FIRMS MAP_KEY](https://firms.modaps.eosdis.nasa.gov/api/map_key/).

```sh
cp .env.example .env          # then put your own key in FIRMS_MAP_KEY (never commit .env)
cd pipeline
uv sync
uv run jangada-check          # checks the key, FIRMS products and dates, yearly files and disk space
uv run jangada-probe          # deeper test: every API source, old dates, transaction cost (~80 transactions)
```

## Tests

Offline, no network and no MAP_KEY needed:

```sh
cd pipeline && uv run pytest   # 21 passed, 6 skipped until the data is built
cd web && npm test             # vitest
```

See [`docs/TESTING.md`](docs/TESTING.md) for the three test layers, Playwright, and the from-scratch
reproducibility check (not yet run on a second machine).

## Data pipeline

```sh
cd pipeline
uv run jangada-download all         # ~20 min: yearly files (5 min, 3.2 GB, no key) + area API (~15 min, paced)
uv run jangada-download crosscheck  # checks API + border clipping against the yearly file (NOAA-20, Sep 2025)
uv run jangada-aggregate            # monthly counts per 0.1° cell and satellite -> data/processed/
uv run jangada-regions              # cell -> Brazilian state (IBGE)
uv run jangada-harmonize            # calibration, held-out validation, harmonized series (docs/METHOD.md)
uv run jangada-export-web           # web/public/data/{manifest.json, observed.parquet, harmonized.parquet}
uv run jangada-municipalities       # IBGE municipality outlines + search index (web/public/data/municipalities/)
uv run jangada-extras all           # spec 002: biomes, recurrence, municipality ranking, validation points, ONI,
                                    # last 7 days, FRP and night share, overpass time (needs `jangada-download yearly`)
uv run pytest                       # offline unit tests + invariants of the exported data (docs/TESTING.md)
```

The download is resumable: stop it and run it again at any time. For long runs on a remote machine:
`setsid nohup uv run jangada-download all > ../data/download.log 2>&1 &`.

## Web app

```sh
cd web
npm ci
npm run dev        # http://localhost:5173 (reads web/public/data, produced by jangada-export-web)
npm test           # vitest: area → cells, month comparison, yearly totals, ranking, CSV
npm run e2e        # playwright: built site, tabs, ranking, map layer, phone drawer, CSV, Method (outside hosts blocked)
npm run build      # typecheck + static build in web/dist (deployed to GitHub Pages by .github/workflows/pages.yml)
```

Stack: React, Vite, TypeScript, Tailwind CSS 4 + shadcn/ui (Radix), MapLibre GL (OpenFreeMap basemap, © OpenStreetMap
contributors), terra-draw, hyparquet. Colors live once in `web/src/styles.css` (Jangada tokens → shadcn variables →
Tailwind theme); the dark theme follows `<html data-theme>`.
Layout (spec 002): from 1024 px three columns (area and layers, map, data); on tablets the map sits above the data and
the filters open in a side drawer; on phones the map comes first and the data opens in a bottom drawer. The data
column has four tabs: Calendar (with the yearly totals and their conversion range), this year so far (with up to three
compared states per 1,000 km²), Season and Ranking. The map can paint each state by this year against normal.
Brazil and the 27 states load from `series.json`. Drawn areas fetch only the 2° × 2° tiles they touch
(`web/public/data/tiles/`, a few hundred KB; GitHub Pages gzips `.parquet`, which rules out HTTP range requests).
The full harmonized and observed datasets stay downloadable as `web/public/data/*.parquet`. No server, no login,
no API key in the browser.
